# PetPulse mini

Учебное приложение — мини-версия программного комплекса PetPulse.
Владелец регистрируется, добавляет своих питомцев и записывает их на приём к ветеринару.

- `server/` — сервер на Node.js + Express, база данных SQLite, авторизация через токен в cookie;
- `client/` — клиент на React (Vite).

## Запуск

Нужен Node.js 20.19 или новее. Сервер и клиент запускаются в **двух разных терминалах**.

Сервер:

```shell
cd server
npm install
npm start
```

Клиент:

```shell
cd client
npm install
npm start
```

Клиент откроется на http://localhost:3000. Запросы на `/api` он пересылает на сервер (http://localhost:3001).

База данных создаётся сама при первом запуске сервера: файл `server/db/database.db`.
Отдельные запросы удобно проверять через `server/requests.http` (расширение REST Client для VS Code) или Postman.

## Роли

| Роль | Как войти | Что может |
|---|---|---|
| Гость | без входа | смотреть каталог врачей |
| Владелец питомцев | зарегистрироваться на странице входа | свои питомцы, запись к врачу |
| Администратор | логин `admin`, пароль `admin123` (создаётся при первом запуске) | добавлять и удалять врачей |

## Структура

```
server/
  index.js              запуск сервера, подключение маршрутов
  db/db.js              подключение к базе и создание таблиц
  routes/               адреса API: какой запрос какой функцией обрабатывается
  middleware/           checkAuth — вошёл ли пользователь, checkAdmin — администратор ли он
  utils/                hashPassword — хеширование паролей
  controllers/          обработчики запросов: проверка данных и ответ
  repositories/         SQL-запросы к таблицам базы
  requests.http         готовые запросы для проверки
client/
  index.html
  vite.config.js        настройки Vite (порт, пересылка /api на сервер)
  src/
    main.jsx            запуск React
    App.jsx             главный компонент: вход или главный экран
    api.js              функция для запросов к серверу
    index.css           стили
    components/
      AuthForm.jsx            вход и регистрация
      Dashboard.jsx           главный экран
      PetsSection.jsx         питомцы
      AppointmentsSection.jsx записи к врачу
      VetsSection.jsx         каталог врачей
      AdminPanel.jsx          панель администратора
```

## База данных

| Таблица | Что хранит |
|---|---|
| users | пользователи (логин, хеш пароля, роль) |
| tokens | токены входа |
| pets | питомцы, у каждого есть владелец (ownerId) |
| vets | врачи (заполняются при первом запуске) |
| appointments | записи на приём: питомец, врач, дата |

## API

| Метод | Адрес | Что делает | Нужен вход |
|---|---|---|---|
| POST | /api/auth/register | регистрация `{ login, password }` | нет |
| POST | /api/auth/login | вход `{ login, password }` | нет |
| POST | /api/auth/logout | выход | да |
| GET | /api/auth/me | текущий пользователь | да |
| GET | /api/pets | мои питомцы | да |
| GET | /api/pets/:id | один питомец | да |
| POST | /api/pets | добавить `{ name, species, breed?, birthDate? }` | да |
| PUT | /api/pets/:id | изменить питомца | да |
| DELETE | /api/pets/:id | удалить питомца (и его записи) | да |
| GET | /api/vets | врачи, фильтр `?specialization=` | нет |
| GET | /api/vets/:id | один врач | нет |
| POST | /api/vets | добавить врача `{ name, specialization, price }` | админ |
| DELETE | /api/vets/:id | удалить врача | админ |
| GET | /api/appointments | мои записи к врачу | да |
| POST | /api/appointments | записаться `{ petId, vetId, date }` | да |
| DELETE | /api/appointments/:id | отменить запись | да |

При записи сервер проверяет, что время не в прошлом и что врач в это время свободен.

## Коды ответов

- `200` — всё хорошо
- `201` — создано
- `400` — неверные данные
- `401` — не выполнен вход или неверный логин/пароль
- `403` — вход выполнен, но не хватает прав (не администратор)
- `404` — не найдено
- `409` — конфликт: логин занят или врач занят в это время
